`Multimodal Agent` `Realtime`

### 跟进｜Jev 首批独立浏览器 Agent 对照：速度优势明显，但成功率远低于 LLM
`System One Model` `Independent Benchmark`

**更新：** AIMultiple 于 9 月 24 日发布 AIM-Decision，对 Jev 1.13、Kev-9B、Laya 与 GPT-6 Astra、Gemini 3.8 Flash 在同一套 50 个 browser-use 任务上进行 250 次测试。Jev 完成 **17/50**，Kev-9B **20/50**，GPT-6 Astra **47/50**，Gemini 3.8 Flash **42/50**；Jev 在部分成功任务中明显更快，但 33 个失败中有 24 个被其判为 blocked，其中 16 个在执行任何动作前就退出。

**判断：** 这是 Jev 目前非常有价值的独立证据：System One 决策模型确实能把单步 action selection 做得很快，但现阶段还不能直接替代通用 LLM 做开放式 browser agent。更合理的工程位置仍是高频、封闭 action space 的 router / classifier，而复杂长程任务保留 LLM fallback。

**来源：** [AIMultiple / AIM-Decision: Jev vs Kev vs LLMs](https://aimultiple.com/decision-models)

### 跟进｜Jev 安全实测：结构化输入并没有天然带来更强鲁棒性
`Agent Safety` `Decision Model`

**更新：** Check Point 于 9 月 24 日公开针对 Jev 的对抗输入实验。在其 due-diligence 场景中，9 种 attacker × difficulty 组合全部至少出现一次成功翻转；最强 attacker 在 27 次运行中成功 25 次，平均第 4 轮突破。将外部文档显式标为 untrusted，或加入 anti-injection 指令，都没有显著改善结果。

**判断：** 这把前几天的“Jev 可能受外部输入影响”推进成了更具体的独立实验。typed decision 解决的是输出形态和速度，不是 trust boundary；如果类似模型用于手机 Agent 的敏感 tool permission，最终授权仍应由 deterministic policy / capability control 决定。

**来源：** [Check Point / A First Look at Jev](https://blog.checkpoint.com/ai-security/jev-is-not-a-language-model-but-it-breaks-like-one-prompt-injection-against-a-typed-decision-model/)

### 跟进｜非当日发布・社区热度上升：CLM-8B 开源复现 System One 路线
`Open Weight` `Agent Router`

**更新：** Contrastive-LM 公开 CLM-8B：以 Qwen3-8B 为 frozen encoder，加约 20M 参数 projection heads，通过 state/action 双编码与 InfoNCE 直接给候选动作打分；代码与 CLM-8B 权重均为 Apache-2.0，并提供 TypeSafe-compatible API。官方称 zero-shot 在 computer-use / gaming / tool-calling 上与 Jev 接近、最高可低约 9× latency；但 81.6% DeepSWE / 87.6% Terminal-Bench 2.1 是经过任务 fine-tune 的 verifier head，不是 zero-shot 成绩。

**判断：** 这比单纯“Jev 很火”更值得继续追：System One 已出现真正 open-weight 的独立路线，而且 state/action embedding 可缓存的结构很适合高频 tool routing。当前 8B + vLLM/NVIDIA GPU 明显不适合手机；更值得等 0.1B–2B backbone 的 CLM-style 复现，再和 Needle 3 做端侧对照。

**来源：** [Contrastive-LM / CLM GitHub](https://github.com/Contrastive-LM/CLM) · [CLM-v0.1-8B 模型卡](https://huggingface.co/Contrastive-LM/CLM-v0.1-8B)

## AI点评

1. **Jev 今天终于有了更有用的第三方证据。** 独立 browser benchmark 同时证明了“快”和“能力边界”：17/50 对 47/50，说明 decision model 现阶段最合理的定位不是替代 LLM，而是把封闭决策从 LLM 中拆出来。
2. **CLM-8B 让 System One 从 proprietary idea 变成了可研究的 open-weight 方法。** 真正值得等的是小 backbone：如果 0.3B–2B 的 contrastive router 能保住大部分 action-selection 能力，它会比 8B 版本更贴近手机 Agent。
3. **Needle 3 与 CLM 代表两种很值得对照的端侧路线。** Needle 3 是极小专用模型直接做 structured tool calling；CLM 是 embedding + candidate scoring。后者尤其适合 tool 集固定、action 可缓存的场景。
4. **Nemotron 3 Diarization 值得加入语音候选池但不算今日新闻。** 100M 左右、streaming、8 speaker 的规格对 meeting/interview ASR 很实用；下一步真正关键的是 Android CPU/NPU 转换难度、中文多人场景 DER 与端侧 RTF。
5. **端侧 Runtime 今天仍没有新的 release/NPU 实证。** 继续坚持“可编译 → 可运行 → full delegation → 实际更快”，不把仓库 activity 或文档刷新包装成部署进展。
