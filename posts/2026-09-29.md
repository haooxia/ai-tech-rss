### Qualcomm GenieX v0.7.1：新增 prefill/decode 指标，修复 VLM 与 Adreno 路径
`GenieX / Qualcomm` `Android / QAIRT`

**更新：** Qualcomm 于 9 月 29 日北京时间约 06:06 发布 GenieX v0.7.1。Release notes 的关键变化包括：server response 新增 **prefill / decode tokens-per-second** 指标；VLM vision encoder 默认从 BF16 改为 FP16；修复 **Adreno 643 的 Q4K OpenCL kernel 编译**并加入 QCS6490 GPU batch defaults；修复 MiniCPM5 XML tool-call 解析；llama.cpp 子模块升级，并为 Windows on Snapdragon 提供 Microsoft-signed HTP catalog。Release 同时提供 Android AAR、Android arm64 benchmark 包，以及独立的 QAIRT Python distribution。

## AI 行业热点

### NVIDIA 发布 Open Agent Safety Platform：把 Agent 权限边界移出模型
`Agent Safety` `Runtime Sandbox`

**更新：** NVIDIA 于 9 月 28 日发布 Open Agent Safety Platform。核心是开源 **OpenShell** secure runtime，用模型外的 runtime boundary 控制 Agent 能访问的数据、工具与服务；参考设计 **Sentry** 运行在 BlueField-4 DPU 上，从独立硬件 trust domain 监控并隔离越界 Agent。NVIDIA 表示 OpenShell 可扩展到 Arm、Intel 等第三方计算平台，并与 Anthropic Claude Managed Agents 等生态合作。

**判断：** 这与最近 decision-model 的安全讨论形成清楚分层：模型或 guard model 可以做“判断”，但真正的 tool permission、filesystem、network 权限应由**模型外 deterministic runtime**执行。它目前主要面向服务器/企业 Agent，不是 Android runtime；但 capability boundary 思路很适合借鉴到手机 Agent。

**来源：** [NVIDIA / Open Agent Safety Platform](https://nvidianews.nvidia.com/news/open-agent-safety-platform) · [NVIDIA / OpenShell GitHub](https://github.com/NVIDIA/OpenShell)

## AI点评

1. **GenieX v0.7.1 是今天与你当前工作最相关的更新。** 建议升级后重新跑现有 Qwen3.5-2B benchmark：server 已原生返回 prefill/decode t/s，更容易与此前数据稳定对照。
2. **这版更像“工程可观测性 + 兼容性修复”，不是 NPU 性能大版本。** QAIRT 包继续存在并不代表 HTP kernel、graph partition 或量化策略发生突破；是否更快仍需要同机型、同模型、同 config 重测。
3. **OpenShell 的架构比单纯再加一个 guard model 更值得 Agent 产品借鉴。** 风险模型可以输出概率或标签，但最终能否调用敏感能力，应由 runtime capability policy 决定。
4. **端侧 Agent 值得把“模型能力”和“权限执行层”拆开评测。** 小模型测 tool-selection accuracy；Android wrapper 单独测 permission、参数校验、敏感动作确认与 fallback。
