## 模型与多模态

### Google 发布 Gemini 4 Argon：1M context 的长程专业工作模型先向安全合作方开放
`Frontier Model` `Long-horizon Agent`

**更新：** Google 于 9 月 30 日正式公布 Gemini 4 Argon，定位为面向复杂、长程工作流的 frontier model，覆盖真实软件工程、法律/金融知识工作和网络安全防御；上下文上限为 **1M tokens**。当前并非全面公开 API：首先通过 Fairwind Program 向受信任的网络安全防御方逐步开放，并参与美国政府的 pre-release access 流程；Google 表示后续才会扩大到开发者、企业和消费者。官方同时给出未来 introductory pricing：**$2/M input、$10/M output，cached input 比 input 低 95%**。

**判断：** 这不是端侧候选，但值得作为移动/端侧 Agent 的云端上限模型观察。更重要的是 Google 把重点从单轮 benchmark 明确推向 **long-horizon workflow**：官方披露 Argon agents 已用于大型 C/C++→Rust 迁移、数据中心内存优化和安全漏洞修复。对手机 Agent 架构的启示仍是本地模型负责低延迟感知/路由，超长任务交给云端强模型；目前不能把 Argon 写成已经面向普通开发者可用。

**来源：** [Google / Introducing Gemini 4 Argon](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/)

## AI 行业热点

### Gemini Skills 开始取代 Gems：可组合、可带参考文件的复用指令成为正式产品层
`Agent Skills` `Reusable Workflow`

**更新：** Google 于 9 月 30 日发布 Gemini Skills，用 `/` 直接调用预先保存的指令，并支持给 skill 附加 reference files、把多个 skills 组合使用；官方明确表示 **Skills 将取代 Gems**，现有 Gems 数据会迁移。Skills 还可以通过分享链接分发，Google 给出的定位已从单纯“自定义人格/提示词”转向可复用的任务工作流。

**判断：** 这和近期 MCP / Skills / Agent runtime 的演化方向一致：稳定工作流正在从超长 system prompt 中被拆成**可命名、可组合、可共享的能力单元**。它目前主要是 Gemini 产品能力，不代表 Android 本地执行；但对端侧 Agent 设计很有参考价值——本地 tool router 可以只选择 skill/action，而把具体长指令和权限策略独立管理。

**来源：** [Google / Automate repetitive tasks with Skills](https://blog.google/products-and-platforms/products/gemini/automate-tasks-with-skills/)

### 跟进｜非官方 Qwen 发布：Qwen3.8-27B-pi 针对 Pi coding agent 做 reasoning-efficiency 微调
`Community Model` `Coding Agent`

**更新：** Hugging Face 上的 `bytkim/Qwen3.8-27B-pi` 在本窗口进入社区视野。它**不是 Qwen 官方发布**，而是基于 Qwen3.8-27B 面向 Pi agent harness 的独立微调：先用成功 Pi trajectories 做 SFT，再以 GRPO 和 reasoning-efficiency reward 强化不同 effort 档位；作者同时提供 BF16、FP8、GGUF，以及 DFlash2 / MTP speculative decoding 路径。模型卡报告在其选定测试中，Pi medium 可用约少 41% 输出 token 达到 base xhigh 的 Terminal-Bench 2.1 完成率。

**判断：** 27B 明显超出本简报 0.1B–4B 的手机候选范围，因此不作为端侧替代模型推荐；值得跟的是它把 **agent trajectory + 可调 reasoning effort + 推理 token 成本**放在同一个训练目标里。这与前几天 small-model reasoning distillation 的趋势相呼应，后续若同类方法下沉到 0.8B–4B，才真正值得手机端验证。

**来源：** [Hugging Face / bytkim Qwen3.8-27B-pi](https://huggingface.co/bytkim/Qwen3.8-27B-pi) · [GGUF](https://huggingface.co/bytkim/Qwen3.8-27B-pi-GGUF)

## AI点评

1. **Gemini 4 Argon 再次强化“长程 Agent”而不是单轮聊天的竞争。** 真正值得继续追的是它公开 API 后的 tool-use、computer-use、价格和长任务成功率，而不是只看一次性 benchmark。
2. **Skills 正在成为跨厂商 Agent 的稳定抽象。** MCP 更像工具/上下文协议，Skills 更像可复用任务知识；手机端若做 Agent，值得把 tool schema、skill instructions、permission policy 三层分开。
3. **Reasoning-efficiency 开始成为模型训练目标，而不只是推理参数。** 近期从 4B reasoning student 到 Qwen3.8-27B-pi 都在优化“完成任务所需 token/步骤”；如果这种方法进入 0.8B–2B，会比单纯扩大端侧模型更值得测试。
4. **端侧 Runtime 今天仍没有新的 release 级 NPU 证据。** 继续坚持“可编译 → 可运行 → full delegation → 实际更快”的判断链，不把仓库活跃度或旧支持页面刷新误报成突破。
