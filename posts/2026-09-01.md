`LiteRT-LM` `Snapdragon`

**更新：** LiteRT Community 新发布 `granite-4.2-3b` 的 LiteRT-LM 转换，提供 2.19 GB int4 与 3.76 GB int8 bundle，并保留 reasoning 的 `thought` channel。Galaxy S26 / Snapdragon SM8850 上两种 bundle 均通过 GPU/CPU 正确性验证，GPU OpenCL 在全部 prefill signature 与 decode 上实现 1783/1783 nodes 全图 delegation、0 rejected op；int4 GPU 实测 prefill 235–241 tok/s、decode 12.3–15.6 tok/s、TTFT 0.93–0.94 s，峰值进程 RSS 约 1.4 GB。

## 音频、翻译与检索

### Microsoft Harrier 0.6B 新增 LiteRT 端侧 Embedding 转换
`Embedding` `LiteRT`

**更新：** LiteRT Community 新发布 Microsoft Harrier 0.6B 的 `.tflite` 转换，面向 100+ 语言的 retrieval / RAG / clustering / semantic similarity；推荐 int8 dynamic-range 版本为 626 MB，输出 1024 维 L2-normalized embedding，当前端侧路径是 CPU/XNNPACK，提供 64/128/256/512 四档静态长度。量化后在其验证集上基本保持 PyTorch 质量：JSTS Spearman 0.8559 vs 0.8553，JSQuAD nDCG@10 0.9360 vs 0.9363。

**判断：** 多语言检索质量和“服务端建库、端侧查询”兼容性很有吸引力，但 626 MB 文件、约 2.4 GiB 峰值内存且只有 CPU 路径，对手机相册/检索场景暂时更适合作为质量上限候选，而不是直接替换更小的端侧 embedding 模型；同时 query instruction 和 `<|endoftext|>` tokenizer post-processor 都必须严格保留。

**来源：** [LiteRT Community / harrier-oss-v1-0.6b](https://huggingface.co/litert-community/harrier-oss-v1-0.6b)

## AI 行业热点

### Tencent 发布 ContextPilot 8B / 14B / E4B：Agent 主动管理工作上下文
`Agent` `Context Management`

**更新：** Tencent 在过去 24 小时正式发布 `ContextPilot-8B`、`ContextPilot-14B`、`ContextPilot-E4B` 三个 checkpoint，分别覆盖 Qwen3-8B、Qwen3-14B 与 Gemma4-E4B 路线。ContextPilot 让长任务 Agent 使用 planning、structured long-term memory、retrieval 与 soft context offloading 主动整理工作上下文；官方同时强调，仅加载 checkpoint 并不会自动执行这些 context-management tools，还需要配套 agent runtime 与工具定义。

**判断：** 这批 8B/14B 级 checkpoint 本身不是手机优先候选，但“主动缩短有效工作上下文”对端侧 Agent 很值得跟踪：它可能同时降低 KV cache、长上下文 RAM 和重复 prefill 成本；若后续出现 1B–4B 版本或移动 runtime 适配，替换价值会明显上升。

**来源：** [Tencent / ContextPilot-8B](https://huggingface.co/tencent/ContextPilot-8B) · [ContextPilot-14B](https://huggingface.co/tencent/ContextPilot-14B) · [ContextPilot-E4B](https://huggingface.co/tencent/ContextPilot-E4B)

## AI点评

1. **Granite 4.2-3B 说明 3B 级 reasoning 模型的手机 GPU 路线已经相当具体。** 但必须继续把“全图 delegation”与“真正 NPU”分开；下一步最值得盯的是同模型能否进入 QNN/HTP 或 LiteRT NPU compiler 路径，以及 NPU 是否真的快于这组 OpenCL GPU 数据。
2. **端侧 Embedding 的验收要把 prompt/tokenizer contract 当作模型的一部分。** Harrier 省略 query instruction 会让 JSTS 与 JSQuAD 都明显下降，而漏掉 tokenizer 自带的 `<|endoftext|>` 又会直接改变 pooled token；这和前一天 LiteRT-LM tokenizer 修复属于同一类隐蔽正确性风险。
3. **Harrier 值得加入相册/语义检索候选池，但先别替换现方案。** 建议优先用真实中文相册 query 做 Recall@K / nDCG、包体、峰值 RAM、单条查询延迟对照；如果质量提升不足以覆盖 626 MB 和 CPU-only 的成本，就没有替换价值。
4. **Context management 可能比继续堆 context window 更适合端侧 Agent。** 对手机而言，减少“当前必须驻留和重复 prefill 的上下文”往往比宣称更大的最大 context 更直接影响体验；后续重点看小尺寸 ContextPilot 类模型以及 context offloading 与移动端 KV cache/runtime 的结合。
