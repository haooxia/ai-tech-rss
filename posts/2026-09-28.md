## 模型与多模态

### Distil Labs 新增小模型短推理训练：4B 多步任务从 45 提升到 95
`Small Model` `Reasoning Distillation`

**更新：** Distil Labs 于 9 月 28 日发布 reasoning-student 训练能力：通过 `enable_thinking: true` 让小模型学习受控、较短的 reasoning trace，而不是仅在推理时打开 thinking。其 Qwen3.5-4B 实验中，一次性回答在 invoice / flight connection 两类多步任务上分别为 **84 ± 3.7 / 45 ± 5.0**，加入同数据规模的 reasoning 训练后达到 **98 ± 1.4 / 95 ± 2.2**，接近对应 teacher 的 97 / 100；未经这种训练、只打开 thinking 的 Qwen3.5-4B 在 2,048-token 预算内分别有 63% / 100% 的样本无法完成。

**判断：** 对 0.8B–4B 端侧模型很有启发：多步、规则型任务的关键可能不是“让小模型多想”，而是把**短、任务化、可控长度的推理轨迹**蒸馏进去，避免 thinking token 失控。Distil Labs 文档已支持 Qwen3.5 0.8B / 2B / 4B 等 student，但今天公开的强结果主要来自 4B 和合成业务数据，不能直接外推到通用能力或手机 NPU；官方 4B grounded-decision 还提供 Q8_0 GGUF（约 4.48 GB），可在 llama.cpp 笔记本运行。

## AI点评

1. **“短推理蒸馏”比单纯开启 thinking 更值得端侧研究。** 这组实验最有价值的地方是：未训练的 4B 模型会把 token 预算耗光，而经过任务化 reasoning trace 训练后，反而用更可控的推理完成多步规则判断。
2. **真正适合手机验证的是 0.8B / 2B，而不是直接搬 4B Q8。** Distil Labs 已支持 Qwen3.5-0.8B / 2B student；但目前高分结果只证明了 4B 路线可行，下一步应看小尺寸是否还能保留这种增益，以及 Q4/INT4 后的质量、RAM 与 latency。
3. **这套方法不应机械套到所有文本任务。** 对发票核验这类多步规则判断很合理；对 ASR formalization 这种核心要求是内容忠实、少改写的任务，显式 reasoning 可能反而增加回归，需要单独用 Win / Regression / Fidelity 验证。
4. **端侧 Runtime 今天仍没有新的 release/NPU 实证。** 继续坚持“可编译 → 可运行 → full delegation → 实际更快”，不把仓库 activity、旧模型重新索引或媒体重报当成当天部署进展。
