## 模型与多模态

### BotPsy-0.8B：面向端侧 Agent 与工具调用的 8 亿参数新模型

**标签：** Small LLM · Tool Calling

**更新：** Tether AI Research 于**11月11日**发布 BotPsy-0.8B 官方文章和模型权重。它基于 Qwen3.5-0.8B，采用 SFT、多教师 On-Policy Distillation 和两轮 RL 训练，发布 BF16 safetensors 及 BF16/Q8_0/Q4_K_M GGUF，模型卡标注 **Apache-2.0**。发布方使用同一评测框架、BF16/vLLM 报告 BFCL v4 **44.0**（底座23.4）、ACEBench **58.7**（底座30.1）、ToolSandbox **64.6**（底座30.5）；拒绝不合适工具的 BFCL hallucination 子项 **86.1**。模型推荐英语，中文仅有多语言指令评测；公开模型卡未提供 Android HTP 真机速度、RAM 或功耗。

**判断：** **本期最值得纳入 SeekPilot 评测的候选**。应与 Needle3、MNN-Pocket 在相同中文工具 schema 下对比单步/多步调用、参数抽取、无工具可用时的拒绝率、首包与功耗。它是 Qwen3.5 Gated DeltaNet + Attention 混合架构，GGUF 可运行不代表 GenieX/HTP full delegation；而且其 thinking 模式可能影响端侧延迟。

**来源：** https://huggingface.co/blog/qvac/botpsy · https://huggingface.co/qvac/BotPsy-0.8B · https://huggingface.co/qvac/BotPsy-0.8B-GGUFs

### Google Gemini Decision 1：专门用于工具路由与多模态决策的新模型/API

**标签：** Decision Model · Agent Routing

**更新：** Google DeepMind 于**11月11日**发布 **Gemini Decisions API** 和专用模型 `gemini-decision-1`。输入支持文本、图片、音频、视频和 PDF（最高256K tokens），一次请求最多 **1,000 个独立问题**，混合 yes/no、2–255选项的 choice 和等级评分；单次前向传播直接返回概率，不逐 token 解码。Google 声称在不超过16K输入、1–100问题的测试下，模型计算中位延迟50–100ms、端到端约150–250ms；定价每百万输入 token **$0.10**、输出 token 不计费。Google Notebook 已用它进行动态模型路由，官方称日常请求延迟最多降低40%。这些都是官方特定设置数据，不是独立真机评测。

**判断：** 与近期 Kakao Kanana-2-v-decide 的方向一致，但**这是新的云端可调用产品**，而不是此前已报模型的重复新闻。对 SeekPilot 可参考“先做有界决策，再调用工具”的设计；也适合作为 Needle3 工具路由与拒绝执行的云端上限对照。模型参数量、权重、手机 NPU 适配未公开，不能视为端侧替换。

**来源：** https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/

## 音频/翻译与检索

### Sentence Transformers v6.3：Token Pooling-Aware Training 压缩多向量检索索引

**标签：** Embedding · Retrieval Compression

**更新：** Hugging Face / Sentence Transformers 维护者于**11月11日**发布新技术文章并宣布 v6.3 的多向量 Token Pooling-Aware Training。它通过对未池化和池化后的文档 token 向量同时施加检索损失，使模型在合并相似向量后仍保留匹配信息。在 ModernBERT-base、12万 MS MARCO triplets、NanoBEIR@13 的示例中，`pool_factor=4` 时文档平均向量数约193→49，普通训练 nDCG@10 **49.03**，pooling-aware **51.23**，相对各自未压缩版本的检索分数保留率从94.6%提高到97.8%。还提供自适应 token budget、Matryoshka 多向量训练及可选 CUDA/Triton kernel。

**判断：** 对文档检索/本地索引内存优化很有价值，但**它主要服务 ColBERT 式多向量检索**，并非 EmbeddingGemma 单向量检索的直接无损替换。若 SeekPilot 后续加入多向量 reranking，可对比索引体积、nDCG/Recall 和端侧检索耗时；CUDA kernel 加速不能直接推广到 Android。

**来源：** https://huggingface.co/blog/token-pooling · https://github.com/huggingface/sentence-transformers

## AI点评

1. **BotPsy 0.8B 是本期最直接的端侧替换候选。** 下一步优先测试中文 tool schema、拒绝调用、多步成功率与 thinking 模式带来的延迟，不能仅凭 BFCL 厂商分数下结论。
2. **专用 Decision Model 值得单独建立评测赛道。** Gemini Decision 1 与 Kanana 的共同方向是直接给选项概率；应比较工具数量变化、缺失工具、拒绝执行与端到端路由延迟，而不是只比 JSON 输出。
3. **多向量检索的索引体积有新的训练优化路径。** 如果 SeekPilot 从单向量扩展到 ColBERT 式 late interaction，可试 Token Pooling + Matryoshka + 量化的组合；先量化 Recall/nDCG 损失。
4. **语音 Agent 正向跨设备、可打断和连续会话演进。** CarPlay 新功能值得观察交互设计，但不能推断 iPhone 或 Android NPU 端侧推理性能。
5. **保持模型与 Runtime 双轨扫描。** 今天六个 Runtime 没更新，但有 BotPsy、Decision API 和检索训练新能力；“无框架更新”不等于“无高价值新闻”。
