## 系统、优化与硬件

### Android CLI 加入 Device Streaming 与官方 Android Skills：通用 Coding Agent 可直接操作真机
`Android Agent` `Device Streaming / Skills`

**更新：** Google 于 10 月 2 日更新 Android CLI：任意支持命令行/skills 的 AI agent 可借助 `android-cli` 创建、构建、测试和管理 Android 项目；新的 **Android Device Streaming** 能从 CLI 连接 Google 数据中心中的真实 Android 设备，并支持安装 APK、运行测试、查看日志和截图。Google 同时扩展官方 **Android skills**，将特定 Android 开发知识封装成 agent 可加载的技能。

**判断：** 这不是手机端推理 runtime，但对 Android Agent 开发链很实用：闭环从“改代码 + emulator”进一步变成 **改代码 → build → 真机执行 → 观察结果**。对端侧 AI 项目尤其适合做设备兼容性、UI、模型加载和 benchmark 自动化；它是云端 Device Streaming，不等于 Agent 在目标手机本地运行。

**来源：** [Android Developers / Device Streaming and Android skills](https://android-developers.googleblog.com/2026/10/android-cli-device-streaming-and-skills.html)

## AI 行业热点

### Pi 1.0 加入 MCP / Codemode / deferred tools，并拆出 Pi Durable
`Coding Agent` `MCP / Long-running Agent`

**更新：** Pi 1.0 在 10 月 2 日披露的新路线中加入原生 MCP，并通过 **Codemode** 让模型编写脚本组合工具调用；同时支持 virtual models、deferred tool loading、Anthropic cache warming，以及在会话中动态插入 system message。长期运行能力被单独拆成实验性的 **Pi Durable**，使用 SQLite / JSONL 管理持久化和多会话。

## AI点评

1. **GenieX v0.8.0 值得升级后专门重测 VLM，而不是只测纯 LLM。** mmproj / LM 分 HTP session 是非常具体的多模态部署变化，建议后续关注它是否改善 VLM 初始化、内存占用、session 冲突或首 token latency。
2. **Agent 工具层正在形成同一个答案：不要把全部 schema 永久塞进 context。** Uber 的大规模 MCP、Pi 的 deferred tools / Codemode、近期 decision model 都在指向“先发现/决策，再加载少量工具”。
3. **Android Agent 的评测闭环正在成熟。** Device Streaming 让 coding agent 能真正操作云端真机；如果再接 benchmark/log parser，很适合自动验证不同 SoC / Android 版本下的端侧模型行为。
4. **今天仍没有新的手机 NPU 性能突破证据。** GenieX 有 HTP 架构变化，但仍应坚持“可编译 → 可运行 → full delegation → 实际更快”的判断链。
