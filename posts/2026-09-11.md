## 端侧框架与运行时

### Ternary-Bonsai-1.7B 新增 LiteRT-LM INT2 手机 GPU 包，完整 context 可到 32K
`LiteRT-LM` `Low-bit LLM`

**更新：** LiteRT Community 在本窗口新出现 `Ternary-Bonsai-1.7B` 的可下载 `.litertlm` 低比特包。推荐版采用 INT2 per-channel 权重、fp32 activation、4096 context，文件约 766 MB；同时提供 32K context 的实验版，其中 INT2-all + fused SDPA + fp16 activation 版本约 564 MB。模型源自 Qwen3-1.7B / Prism ML Ternary-Bonsai，Apache-2.0。

**判断：** 这是一个值得加入 Android 小模型部署测试池的超低比特候选，但当前路径明确是 **mobile GPU accelerator**，不是 QNN/HTP NPU；模型卡也没有给出手机 tok/s、RAM 或功耗，因此目前只能确认“可打包/可运行路径”，不能判断它是否比常规 int4 更快。

**来源：** [LiteRT Community / Ternary-Bonsai-1.7B](https://huggingface.co/litert-community/Ternary-Bonsai-1.7B)

## 音频、翻译与检索

### Giga-Embeddings 480M 新增 LiteRT / LiteRT-LM：Galaxy S26 CPU 单条约 68–84 ms
`Embedding` `LiteRT-LM`

**更新：** LiteRT Community 过去 24 小时明确 `published a model`：`Giga-Embeddings-instruct-480M-0826`，提供 512 MB int8 `.tflite` 与 509 MB LiteRT-LM `EmbeddingEngine` bundle。Galaxy S26 / Android 16 上使用 LiteRT-LM 0.17.0 CPU 路径，初始化约 2.6 s，64 token 以内文本单条约 68–84 ms；int8 在其 SciFact-derived 小型检索测试中保持 fp32 的 nDCG@10 0.8450、Recall@5 0.9000，10 条校验样本与 fp32 的平均 cosine 为 0.9944。

**判断：** 这是 LiteRT-LM 0.17.0 新 `EmbeddingEngine` 能力的一个很具体手机落地案例，tokenization、pooling 与 L2 normalization 都能封装进 bundle；但基础模型主要面向俄语/英语，当前仅 CPU/XNNPACK，没有 GPU/NPU 数据，因此不适合作为中文相册检索方案的直接替换，却很值得参考其端侧 embedding pipeline。

**来源：** [LiteRT Community / Giga-Embeddings-instruct-480M-0826](https://huggingface.co/litert-community/Giga-Embeddings-instruct-480M-0826)

## AI 行业热点

### DeepSeek 发布 V4.1-Flash：552B MoE、8B/16B 非对称激活，KV cache 降至上一代约 1/4
`Frontier Model` `Multimodal`

**更新：** DeepSeek 9 月 10 日正式发布并开源 `DeepSeek-V4.1-Flash`：552B MoE，采用新的 Causal Encoder–Decoder 架构，prefill 每 token 激活约 8B 参数、decode 约 16B，原生图文多模态并支持最高 1M context；官方称全局 KV cache 降至约 890 bytes/token，约为 V4-Flash 的 1/4，持久化缓存占用约降至 1/8。模型以 MIT License 发布，并已上线 API。

**判断：** 它不是手机模型，但“输入和输出采用不同激活规模 + 极端 KV cache 压缩”很值得端侧架构关注：对长上下文 Agent，内存与缓存带宽往往比纯 FLOPs 更先成为瓶颈；不过 552B 总参数仍决定它属于服务器级方案，不能因为 8B/16B activated params 就视为 8B/16B 端侧模型。

**来源：** [DeepSeek / Introducing DeepSeek-V4.1-Flash](https://www.deepseek.com/en/news/deepseek-v4-1-flash/) · [Hugging Face / DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)

### Cognition 发布 SWE-2：把多档 reasoning effort 放进一次 RL 训练
`Coding Agent` `RL`

**更新：** Cognition 9 月 10 日发布 SWE-2，基于 Kimi K3 做后训练，并首次把 RL 扩展到 multi-trillion-parameter regime；其新方法在一次训练中联合优化多个 reasoning-effort 档位。官方报告 FrontierCode 1.1 Main 50.0%、DeepSWE 1.1 73.0%、Terminal-Bench 2.1 92.8%，并称 FrontierCode 上与 Fable 5.1 相差不到 1 个百分点、成本低 64%。

**判断：** 真正值得关注的不是又一个 coding model，而是训练目标开始显式优化“能力—推理成本 Pareto frontier”；这种 reasoning effort 可调节机制如果下沉到小模型，可以直接对应手机上的功耗、时延和质量动态档位。

**来源：** [Cognition / Introducing SWE-2](https://cognition.com/blog/swe-2)

## AI点评

1. **LiteRT-LM 0.17.0 开始不只是 LLM runtime。** Giga-Embeddings 的 `.litertlm` bundle 说明 `EmbeddingEngine` 已能把 tokenizer、pooling、normalization 一起封装，这对移动端 embedding 服务的工程简化价值可能比单次 latency 提升更大。
2. **低比特权重需要继续和真实 kernel 分开看。** Bonsai 1.7B 的 INT2 包很小，但 GPU 实际仍以 fp16/fp32 activation 计算；“INT2 权重”不等于“INT2 算力路径”，最终价值仍要等手机 tok/s、峰值 RAM 和功耗。
3. **DeepSeek V4.1-Flash 的 KV cache 设计比 activated params 更值得端侧借鉴。** 手机长上下文首先受 RAM 与内存带宽约束，CED、跨层 KV 复用、稀疏索引和低比特 KV 的组合值得持续关注是否会被小模型采用。
4. **开放 PR 仍然不能算 NPU 已支持。** Pixel 9 / Tensor G4 的 Gemma3-1B 数据很漂亮，但在 artifact 真正合并、设备 dispatch 兼容性得到验证之前，只能定义为“可编译并有实验实测”，不能升级成正式 runtime 支持。
5. **reasoning effort 正从 API 参数变成训练目标。** SWE-2 将不同 effort 档位联合进一次 RL 训练，这种能力—成本曲线如果能在 1B–4B 模型复现，会非常适合端侧根据温度、剩余电量和任务复杂度动态选择推理预算。
