### 补报：Qualcomm GenieX v0.6.1 发布，Android 直接提供 QAIRT/NPU SDK 包
`GenieX` `Snapdragon NPU`

**更新：** Qualcomm 于北京时间 9 月 4 日 06:41 发布 GenieX v0.6.1；该 release 落在昨日简报统计窗口内但未被昨日简报覆盖，因此本次补报。Release 直接提供约 81.9 MB 的 Android AAR、Android ARM64 benchmark 包以及 CPU-only AAR；当前 GenieX 官方路径明确区分两套 runtime：`qairt` 使用 Qualcomm AI Hub 预编译的 per-chipset bundle，运行于 Hexagon NPU；`llama_cpp` 则面向 GGUF，可选择 NPU / GPU / CPU。官方列出的 Android 平台包括 Snapdragon 8 Elite 与 8 Elite Gen 5。

**判断：** 这是近期与手机 NPU 最直接相关的框架更新之一，而且比“支持硬件加速”更具体：QAIRT 路径明确是 **NPU-only**，Android SDK 也已有正式 release artifact。但 v0.6.1 本身没有给出新的模型级 SM8750 / SM8850 latency、prefill/decode 或功耗数据，因此目前能确认的是“正式可集成、存在 NPU runtime 路径”，不能进一步推导为“某个模型 full delegation 或一定快于 GPU”。

## AI点评

1. **GenieX 现在应该重新升到端侧框架跟踪的最高优先级。** 它把 GGUF 的广覆盖和 QAIRT 的 Snapdragon NPU 专用路径放在同一套 SDK 里，对 Android 产品比单独研究 QNN/HTP 底层接口更接近可落地形态。
2. **下一步最需要的不是再确认“GenieX 支持 NPU”，而是模型级实测。** 建议重点盯 SM8750 / SM8850 上 Qwen3.x、Spark-X2.5、K2 Horizon 等候选的 QAIRT bundle、full delegation、prefill/decode、峰值 RAM 和功耗；只有这些数据出来后才能真正比较 GenieX 与 LiteRT-LM / MNN。
3. **Agent 安全开始变成 runtime 问题，而不只是模型 alignment 问题。** 当 Agent 能持续操作外部系统时，权限边界、动作审计、身份隔离和 rollback 会像 tokenizer / preprocessing 一样成为产品正确性的一部分。
4. **今天没有值得硬凑的新模型。** 近期端侧候选已经比较集中在 Spark-X2.5、K2 Horizon、LFM2.5 等；在下一批真正有质量或部署证据的新模型出现前，更有价值的是把这些候选拉到同一手机、同一量化和同一任务集上横向测。
