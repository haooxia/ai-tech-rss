## 其他端侧框架

### llama.cpp：Adreno OpenCL FlashAttention Prefill 获得实测加速

`#llamacpp` `#Adreno`

**事实摘要：** llama.cpp 的 OpenCL backend 合入 FlashAttention Prefill K-tile local-memory transpose 优化，并进入 b10357 正式构建。实现把 K tile 在 local memory 中重新排布，使相邻 KV 行可通过更宽的读取完成，同时保持 FMA 顺序不变；官方 PR 报告输出 bit-identical。

在 Qualcomm 实测中，**Adreno X2-90** 的 pp4096 从 **485.4 提升到 528.3，约 +8.8%**；**Adreno 840** 的 pp4096 提升约 **+5.4%～+8.6%**，而 tg32 基本不变。更早的 fleet 数据中 X1-85 在 pp4096 / pp8192 上分别约 **+8.6% / +11.5%**。该优化默认用于 `DK ≤ 128`，DK=256 因实测负收益继续走旧路径。

**为什么重要：** 这是今天与 Android / Snapdragon 最直接相关的更新。它优化的是 **Prefill，而不是 Decode**，因此更可能改善长 Prompt、摘要、RAG 输入和多轮长上下文的首 Token 延迟；对短 Prompt 的体感会弱一些。从 PR 分支来源也能看到该优化来自 Qualcomm 的 llama.cpp 工作分支。

**手机部署判断：** 已经不是“理论上可能受益”，而是**已有 Adreno X2-90、840 真机/原生 ARM64 实测**。如果走 llama.cpp + OpenCL/Adreno 路线，这一版值得升级测试。

**来源：** llama.cpp 官方 Release / 官方合并 PR  
**来源等级：一级**

### llama.cpp 修复 EXAONE 4.5 的 Sliding Window Attention 未真正启用

`#VLM` `#Correctness`

**事实摘要：** llama.cpp b10361 修复 EXAONE 4.5 加载 MTP head 时 SWA（Sliding Window Attention）配置判断顺序错误的问题。此前日志里 `n_swa` 看起来正常，但内部 `swa_type` 实际仍可能保持为 `NONE`；官方 EXAONE 4.5 GGUF 同样受影响。

问题来自模型层数在读取 `nextn_predict_layers` 前后含义不同：EXAONE 4.5 的 GGUF 带 MTP head，`block_count=65`、`nextn=1`，导致原先按 64 层判断 SWA 的逻辑被跳过；EXAONE 4.0 不含 MTP，因此不受这一具体问题影响。

**为什么重要：** 这是典型的“**日志看起来配置正确，但实际计算图没有启用对应 attention 模式**”问题。EXAONE 4.5 本身是 33B VLM，不属于典型手机模型，但这次修复对 llama.cpp 处理中 **MTP + SWA** 架构组合的正确性有参考意义。EXAONE 4.5 官方模型为 33B，总体上更适合桌面/工作站而非手机。

**来源：** llama.cpp 官方 Release / 官方 PR  
**来源等级：一级**

## LLM / VLM

### NVIDIA 发布 Nemotron 3.5 Lightning：30B 总参数、3B 激活

`#Nemotron` `#MoE`

**事实摘要：** NVIDIA 于 **8 月 11 日**正式发布 **Nemotron 3.5 Lightning 30B-A3B**。模型采用混合架构，在 MoE 层之外交错使用 Mamba-2 和部分 Attention 层，总参数约 **30B、每 Token 激活约 3B**；同时发布多套 speculative decoding 方案。

官方提供 BF16 参考权重，以及面向低延迟推理的 **NVFP4** 版本；同时提到 W4A16 可用于更广泛硬件。NVIDIA 将 BF16 版定位为微调、蒸馏和自行生成量化/GGUF 权重的基准起点。

**为什么重要：** 3B active 让它的单 Token 计算量显著低于传统 30B dense，但 **30B 总权重仍然必须驻留**，所以不能因为“A3B”就把它理解成普通 3B 小模型。它更适合单卡桌面、工作站或 DGX Spark 一类设备，而不是当前手机端。

此外，llama.cpp 此前已经加入 Nemotron 系列 MTP 支持，这意味着该系列后续进入 GGUF / speculative decoding 生态的基础条件已经具备。

**来源：** NVIDIA 官方 Hugging Face / NVIDIA-NeMo 官方仓库  
**来源等级：一级**

## seek 点评

- 今天最值得实际验证的是 **llama.cpp OpenCL FA Prefill 优化**。5%–9% 级别的真机 Prefill 提升已经足够影响端侧摘要、长 Prompt 和 RAG 的体验，而不是只停留在 kernel microbenchmark。
- 这个优化来自 Qualcomm 分支并在 **Adreno X2-90 / 840** 实测，对 Snapdragon 手机路线的参考价值明显高于普通 CUDA 优化。
- **Active parameters ≠ 手机模型大小。** Nemotron 30B-A3B 每步只激活约 3B，但总权重仍然是 30B；判断手机部署潜力时必须同时看 total params、量化后 ROM 和 RAM，而不能只看 active params。
- MTP、SWA、MoE 等结构组合越来越容易出现“模型能加载但计算图配置不对”的隐性 bug；近期 llama.cpp 的更新值得更多关注**正确性**，而不仅仅是 tokens/s。
- LiteRT-LM、MNN 和 GenieX/QNN 今天都较安静；近期更值得等的是 **Adreno OpenCL 优化是否继续下放到更多算子，以及 HTP/NPU 路线能否出现类似可复现的手机实测提升**。
