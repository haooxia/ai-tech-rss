## 音频、翻译与检索

### Hy-MT2-1.8B 新增 LiteRT-LM 端侧转换
`#机器翻译` `#LiteRT-LM`

**更新：** LiteRT Community 于本窗口发布 `litert-community/Hy-MT2-1.8B`，将 Tencent `Hy-MT2-1.8B` 转成可直接由 LiteRT-LM 运行的 `.litertlm`；模型卡称这是 Hugging Face 上首个 Hy-MT2 的 LiteRT 形态。当前文件为动态 INT8，大小 1.82 GB、最大 token 数 4096；在 Apple M4 Max 上实测 GPU prefill 约 2003–2008 tok/s、decode 约 105 tok/s，CPU decode 约 32–34 tok/s。

**判断：** 对端侧翻译非常值得跟进：它证明 Hy-MT2-1.8B 已能走 stock `litert-torch` → LiteRT-LM 的转换链路，但当前证据仅到 M4 Max CPU/GPU，尚无 Android、Snapdragon QNN/HTP 或手机 NPU benchmark；1.82 GB 的 INT8 体积也意味着下一步真正关键的是 INT4/更低比特与手机真机验证。

**来源：** [LiteRT Community：Hy-MT2-1.8B](https://huggingface.co/litert-community/Hy-MT2-1.8B)

### NVIDIA 发布 100M 流式说话人分离模型
`#Speech` `#Diarization`

**更新：** NVIDIA 于 8 月 27 日发布 `Nemotron-3-Diarization-preview`，是 100M 参数的流式 speaker diarization 模型，支持离线和流式推理、最多 8 个说话人，并可把输入缓冲延迟配置到 0.32 秒。官方 DIHARD III 全集 DER 在 30.4 秒配置下从旧 Streaming Sortformer 的 19.09 降至 12.90；AliMeeting Near 在 1.04 秒配置下从 12.47 降至 7.21。

**判断：** 100M 尺寸和流式能力对 ASR 后处理/多人会议链路很有吸引力，但目前运行路径是 NeMo + NVIDIA GPU，且许可证明确只允许内部测试评估、不可用于生产，因此暂不能作为手机端产品替换候选。

**来源：** [NVIDIA：Nemotron-3-Diarization-preview](https://huggingface.co/nvidia/Nemotron-3-Diarization-preview)

## AI 行业热点

### Anthropic 预览 MHS：把 Agent 协议扩展到真实硬件
`#Agent` `#MCP`

**更新：** Anthropic 于 8 月 27 日开放 Model Hardware Standard（MHS）research preview，目标是让 AI agent 用统一规范发现并安全操作显微镜、液体处理器、机械臂等物理设备。MHS 与模型无关，可由 agent harness 通过 MCP 等标准协议接入；Anthropic 计划在预览阶段后开源，并已披露 AWS Strands Robots、Automata、Doosan、QIAGEN、Tecan 等参与适配。

**判断：** 这不是端侧推理更新，但属于 Agent 生态的重要方向：MCP 正从“软件工具/API 接入层”继续向物理设备控制延伸；真正的生态价值取决于 MHS 开源后是否形成跨厂商驱动与安全权限模型。

**来源：** [Anthropic：Previewing the Model Hardware Standard](https://www.anthropic.com/news/model-hardware-standard-research-preview)

## AI点评

- Hy-MT2-1.8B 的价值首先是“转换链路被实际打通”，不是 M4 Max 上的绝对速度；对手机端下一步应优先验证 INT4、Android GPU，以及 SM8750/SM8850 上是否能形成可用的 NPU delegation。
- 当前 Hy-MT2 INT8 包仍有 1.82 GB，离 100MB 级端侧 ASR 那种部署成本完全不是一个量级，因此它更适合作为翻译质量/部署能力实验候选，而不是直接替换现有轻量 NMT。
- Nemotron-3-Diarization 说明 100M 级专用 speech 模型仍能在流式多人场景取得明显收益；如果后续出现宽松许可证、ONNX/LiteRT/ExecuTorch 版本，会比现在更值得手机端验证。
- MHS 值得观察的不是“又一个协议”，而是 MCP 风格的 agent interoperability 是否会真正进入机器人、实验室和工业设备，并形成跨厂商生态。
