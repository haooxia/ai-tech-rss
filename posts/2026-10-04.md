## 模型与多模态

### Aleph Alpha 发布 Kolibri：78B MoE 仅 3.46B active，Apache 2.0 开放权重
`Open Weight` `MoE / Long Context`

**更新：** Aleph Alpha 于 10 月 3 日正式发布 Kolibri-1：**78.1B 总参数、约 3.46B active/token**，50 层、384 个 routed experts、每 token 激活 6 个；完整权重以 Apache 2.0 发布。模型训练长度最高 262K，可配置到 **1,048,576 tokens**，并提供 none / low / medium / high 四档 reasoning effort、tool calling 与专用 vLLM plugin。FP8 权重约 78 GB，因此“3.46B active”并不意味着它是 3.46B 尺寸模型。

**判断：** 它的 active 参数量落在移动模型关注区间，但 **78B 总权重**直接排除了当前手机本地部署。真正值得跟的是“超大 MoE + 很低 active ratio + 可调 reasoning effort”这条效率路线；如果后续出现总权重真正压到 1B–4B 的衍生模型，再值得做 LiteRT/MNN/QNN 验证。

## AI点评

1. **active parameters 不能直接当作端侧模型大小。** Kolibri 是很典型的反例：3.46B active/token 看起来像手机候选，但 78B 总权重决定了它仍是服务器模型；评估 MoE 端侧价值必须同时看 total weights、active params、KV cache、expert routing 和实际内存。
2. **可调 reasoning effort 正在进入 open-weight 模型本身。** Kolibri 的 none/low/medium/high 与近期 reasoning-efficiency 路线呼应；如果这一机制真正下沉到 1B–4B，对手机端动态平衡 latency / quality 会很有价值。
3. **Persistent Agent 的架构正在快速商品化和开源化。** OpenAI dots 后很快出现 OpenDots 并形成社区热度，“独立 computer + 持久状态 + 权限 + 多终端控制面”越来越像通用 Agent 基础设施。
4. **端侧 Runtime 今天仍没有新的 NPU release 级突破。** 继续坚持“可编译 → 可运行 → full delegation → 实际更快”的判断链。
