### Baseten 开源 joey-1：面向工具路由的约 2B 单次前向决策模型

**标签：** Decision Model · Tool Routing

**更新：** Baseten 于10月29日正式发布 joey-1，基于 Qwen3.5-2B 后训练，输入文本或图像及多个 choice/yes-no/score 问题，一次前向返回候选概率和置信度，不依赖逐 token 生成自由文本；权重采用 MIT 许可。官方模型卡列出16,384 token 上限、Jev Decision Index 0.4 公共集得分63.30；其托管 API 对约2,000-token 请求的 P50 20ms 属厂商云端数据。Hugging Face 自动统计显示约3B参数，与产品的“2B”标称存在口径差异，精确规模仍待核对。

**判断：** 对 Needle3 式工具选择、Search Everything 查询路由和低置信度升级策略有直接替换研究价值；但当前官方自部署流程要求 CUDA GPU，未证实 Android、LiteRT、QNN/HTP 或 GenieX 支持，更不能将云端20ms视为手机延迟。建议用中文工具 schema、拒答阈值和多工具冲突样本与 Needle3/d1 做同集对照。

**来源：** https://www.baseten.co/blog/decisions-for-a-penny-introducing-joey-1/ · https://huggingface.co/baselabs/joey-1

### MNN 3.6.2 正式发布：Hexagon、Metal、DFlash 与多模态覆盖大升级

**标签：** Mobile Runtime · Hexagon NPU

**更新：** MNN 于10月29日17:38（北京时间）发布3.6.2。Release Notes 列出 Hexagon INT4 GEMV、GatedRMSNorm、norm+RoPE 融合、HMX/分块 prefill、Qwen3.5 gated delta rule 与 LFM2 short convolution；Metal Tensor API、低比特算子和 DFlash 投机解码亦得到优化，并新增 Qwen3-ASR、Qwen3-TTS-12Hz-0.6B、Qwen3-VL-Embedding、MiniCPM-V 4.7 等导出/推理支持。官方在 iPad Pro M5 上测得 Qwen3.5-2B Metal prefill 3542.91 tok/s，DFlash decode 从111.89升至233.98 tok/s（2.09倍）；旧版 DFlash 草稿权重需重新导出。

**判断：** 这是本期最值得做端侧验证的正式框架升级，尤其适合在 SM8750/SM8845 测 Qwen3.5、ASR/TTS 与 HTP/CPU/GPU 分工。但 iPad GPU 的2.09倍不能外推为手机 Hexagon 提速；OnePlus 13 的 CPU/OpenCL/Hexagon 对照在官方图表中，仍应复核具体模型、量化、分区/fallback、prefill/decode、RAM 与功耗，区分“支持算子”“模型可运行”“full delegation”和“确实更快”。

### LFM3-Audio-2B 新增 LiteRT 转换：Galaxy S26 跑通混合 NPU 语音输出

**标签：** On-device Speech · LiteRT

**更新：** LiteRT Community 在本窗口新公开 **LFM3-Audio-2B-LiteRT**：约1.53GB 的 INT4 decoder/INT8 embedder .litertlm 支持文本或音频输入、文本输出，另以多个 LiteRT 图完成语音输出。转换者10月29日测得 Galaxy S26（SM8850）GPU prefill **1295.4 tok/s**、decode **40.61 tok/s**、TTFT **0.81–0.82s**；30秒音频编码94.4ms；Android 语音输出采用 CPU decoder + **SM8850 NPU depth pass（396/396算子）** + GPU codec，约 **0.40s 计算生成1s语音**，首段音频约0.71s。Pixel 8a 对应语音生成约1.37s/秒、首段2.06s。发布者仅验证英语，且模型上下文被缩至2048 tokens。

**判断：** 这是值得直接对照现有 ASR→NMT→TTS 的真实 Android 混合后端案例，但 NPU 只覆盖 depth pass，**不代表整模型 full delegation**；音频输入固定30秒窗口，短句也会按完整窗口执行。数据为转换者少量样本自测，不是独立 benchmark；应测中文/粤语、真实 FTL、WER、持续功耗、GPU 显存及多轮状态。源模型采用 LFM Open License v1.0，商业使用存在收入条件。

## AI点评

1. **先验证 MNN 3.6.2 的真实手机收益。** 用同一模型与量化比较 SM8750/SM8845 的 Hexagon、OpenCL、CPU，记录 graph partition、fallback、prefill/decode、冷启动、内存和电流，避免跨设备引用 iPad GPU 的2.09倍数字。
2. **语音端侧正在从单模型 benchmark 走向混合执行链路。** LFM3-Audio 的 NPU depth pass + CPU/GPU 组合很有参考价值，但固定30秒窗口、状态污染和首包时间可能比峰值 tok/s 更影响体验。
3. **决策模型值得加入工具选择基线。** joey-1 可与 Needle3、LFM d1、MiniCPM-OCR Jev 分别比较“选工具、拒答、置信度校准、中文 schema”，尤其关注单次前向是否真的降低端到端成本。
4. **GPU 运行时与 NPU 证据要严格分开。** WebGPU 新算子、MNN Hexagon 路径、GenieX MTP 是不同层级的能力，只有真机图分区和吞吐/功耗才能证明替换价值。
5. **移动 Agent 的交互对象正在扩展。** Gemini PDF 直接编辑与 Gallery XR 语言教师提示：下一步不只是更强模型，还包括文档/语音对象的可操作接口、上下文管理和可观测性。
