## 模型与多模态

### AWS Strands Decider 2B：Jev 路线出现首个大厂开源 2B 决策模型
`Decision Model` `Local Agent`

**更新：** AWS Strands Labs 于 10 月 1 日发布 **Strands Decider 2B**。模型实际约 **1.9B 参数**，以 Qwen3.5-2B-Base 为 torso，移除语言生成 head，替换为约 1M 参数的 pointer head；输入文本后直接在候选项之间做 choice / yes-no probability / score，而不是逐 token 生成。官方仓库给出的 RTX 3090 median latency 为 **115 ms**，并明确支持 Apple Silicon Mac 与 CPU；权重、训练数据和训练脚本均开放，可本地重训。

**判断：** 这是今天对端侧 Agent 最值得关注的变化。它与最近持续跟踪的 Jev、Ollaya、OpenAI Decisions API 属于同一条 System One / decision-model 路线，但 Strands 的差异是**完整开源、可本地运行和可重训**。1.9B 已进入手机可研究的参数范围，不过当前官方证据只到 CPU / Apple Silicon / RTX 3090，尚没有 Android、LiteRT/MNN/QNN/HTP 的可运行、full delegation 或真机功耗/延迟数据，因此暂不能写成手机端已可部署。

**来源：** [Strands Labs / strands-decider](https://github.com/strands-labs/strands-decider)

## AI 行业热点

### Uber 公布 MCP Gateway：800+ MCP servers、5000+ tools 后，工具发现与 context 成本成为新瓶颈
`MCP Infrastructure` `Agent Runtime`

**更新：** Uber 于 10 月 1 日公开其内部 **MCP Gateway** 架构，目前承载 **800+ MCP servers 和 5000+ tools**。平台把 MCP Registry 作为 control plane、Proxy Gateway 作为 data plane，可把既有 HTTP / gRPC / TChannel API 自动转换为 MCP tool；AutoCrawler 会扫描内部 IDL registry 生成工具定义，而每个工具默认 disabled，必须由服务 owner 审核启用。Uber 同时明确指出规模扩大后的三个新问题：跨 server discovery、工具 schema 占用大量 context token，以及安装/配置成本。

**判断：** 这比“又一个 MCP server”更值得跟踪，因为它暴露了生产级 Agent 在数千工具规模后的真实问题：**工具不是越多越好，下一阶段关键是动态 discovery / tool retrieval、最小化 schema context、集中权限与可观测性。** 对手机 Agent 也很相关——端侧小模型没必要看到全部 tool schema，更合理的是先做低成本 tool/skill routing，再只加载候选工具。

**来源：** [Uber Engineering / Designing MCP Gateway](https://www.uber.com/us/en/blog/designing-mcp-gateway/)

## AI点评

1. **Decision model 已经从 Jev 的单点创新迅速变成一个明确模型类别。** OpenAI 做 hosted Decisions API，AWS 则直接给出可重训的 1.9B open model；接下来最值得做的是把 Strands Decider 2B、Needle3 和普通 1B–2B instruct model 放到同一套 tool-selection 数据上测 accuracy / latency / RAM。
2. **Strands Decider 2B 很适合成为新的 Android 移植候选。** 它没有 autoregressive decode loop，本质是 torso + pointer head；如果结构能顺利导出，端侧收益可能不只是模型小，而是一次 forward 就完成决策。但在实际转换前不能假定 LiteRT/MNN/QNN 已支持其自定义 head。
3. **MCP 大规模部署正在从“协议问题”转成“检索和权限问题”。** 5000 个 tool schema 不可能全部塞进小模型 context；tool retrieval / hierarchical routing 会直接决定移动 Agent 是否能扩展。
4. **端侧 Runtime 本窗口仍没有新的 NPU release 级突破。** 继续按“可编译 → 可运行 → full delegation → 实际更快”四层判断，避免把仓库活跃度误当成手机 NPU 进展。
