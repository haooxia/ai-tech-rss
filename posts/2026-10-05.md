## 模型与多模态

### Reflection AI 发布 Beam：501B MoE / 23B active，主攻 Coding 与 Agent
`Open Weight` `MoE / Agent`

**更新：** Reflection AI 于 10 月 5 日发布首个模型 **Beam**：稀疏 MoE，**501B 总参数、23B active**，面向 coding、reasoning 与 agentic workloads；预训练使用 23.8T tokens，官方称高计算量 RL 阶段在 10.5K NVIDIA GB300 上生成超过 1 亿次 rollout。Beam 当前仍在 final red-teaming / evaluation，早期访问通过 waitlist；Reflection 表示将在本月稍后发布权重、技术报告、模型卡和开发者 artifacts，计划采用 Apache 2.0，因此今天不能写成“权重已经可下载”。

**判断：** Beam 不是移动端候选：23B active 已超出本简报 0.1B–4B 的重点区间，501B 总权重更决定了其服务器定位。真正值得跟的是 **agent 能力 / inference compute** 的效率竞争——Reflection 声称 Beam 在高级 reasoning benchmark 上接近 GLM-5.2，同时使用约 3–4× 更少 inference compute；这一结论目前主要来自厂商 benchmark，需等权重发布后的独立复现。

### 跟进｜AIM-Decision 扩展到 22 个决策模型：Jev / Kev 路线开始出现横向 benchmark
`Decision Model` `Agent Evaluation`

**更新：** AIMultiple 的 AIM-Decision benchmark 在 10 月 5 日更新，当前覆盖 **22 个 decision models、1,655 个分类问题**，其中 19 个模型还参与 50 个 browser tasks。它把 Jev、Kev 等 System One / decision model 与 LLM 放进统一的 fixed-choice 与浏览器任务框架中比较，为最近连续出现的 Jev、Ollaya、OpenAI Decisions API、Strands Decider 2B 提供了更系统的横向评测入口。

## AI点评

1. **Open-weight frontier 正把竞争点从总参数转向 inference compute efficiency。** Beam 的 501B/23B MoE 很典型，但对移动端仍然太大；真正值得等的是这种训练/路由效率能否下沉到总权重 1B–4B。
2. **Decision model 已经需要独立 benchmark，而不能继续只靠厂商 demo。** AIM-Decision 开始把 Jev / Kev 等模型放进同一任务集合；下一步更需要手机真机 latency、RAM、power 与 task success 联合指标。
3. **Agent benchmark 要区分“选对动作”和“最终任务成功”。** fixed-choice accuracy 很适合测 router，但 browser task 会暴露状态变化、连续动作和错误恢复能力；端侧 Agent 选型应同时测两层。
4. **端侧 Runtime 今天仍没有新的 release 级 NPU 突破。** 继续坚持“可编译 → 可运行 → full delegation → 实际更快”的证据链。
