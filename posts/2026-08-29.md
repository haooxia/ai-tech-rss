## 模型与行业热点

### Tencent 发布 Hy4 preview：770B MoE、49B 激活、1M 上下文
`#Tencent` `#MoE` `#LLM`

**更新：** Tencent Hy Team 发布 Hy4 preview，并同时提供 BF16 与 FP8 权重。模型主干为 770B 总参数、每 token 激活 49B，包含 78 层；除首层外，其余 77 层均为 MoE，每层 256 个路由专家 + 1 个共享专家，每 token 激活 top-8 路由专家。模型还内置 1 层 MTP 用于 speculative decoding，注意力采用 Gated DeepSeek Sparse Attention，并加入 IndexCache 跨层复用稀疏索引；原生上下文长度为 1M。模型采用 Apache-2.0。

**判断：** 这是今天最重要的新模型发布，但对手机端没有直接替换价值：49B 激活参数和 770B 总权重决定它属于服务器级旗舰模型。更值得跟的是它在 Gated DSA、IndexCache、MTP 与 MoE 上的效率设计，后续若下放到小尺寸 Hy4 系列，才可能进入端侧候选范围。

**来源：** [Tencent Hy4 preview](https://huggingface.co/tencent/Hy4-preview) ｜ [Hy4 preview FP8](https://huggingface.co/tencent/Hy4-preview-FP8)

## 端侧框架与运行时

### Nanbeige4.2-3B 新增 LiteRT-LM 端侧包，并完成 SM8850 GPU 验证
`#LiteRT-LM` `#SM8850` `#SmallLLM`

**更新：** LiteRT Community 新增 Nanbeige4.2-3B 的 LiteRT-LM 版本。该模型是 3B 级 looped-transformer reasoning model，22 层每 token 执行两轮；主 `model.litertlm` 约 2.4 GB，采用 block-32 INT4 权重 + OCTAV clipping、INT8 embedding，并配置 4096-token KV cache。Galaxy S26（SM8850 / Android 16）上，`model_fp32act.litertlm` 可由 LiteRT GPU 完整 delegation：4716/4716 ops、2 个 subgraph，峰值内存约 2691 MB。

**实测细节：** SM8850 上 GPU 的 decode 约 3.91 / 3.31 tok/s，同机 CPU control 约 3.45 tok/s，速度基本打平；GPU 的明确优势是内存，约 2590 MB 对 CPU 的 4152 MB。标准 `model.litertlm` 虽可完整 delegation，但生成阶段会输出 `<unk>`，只有 FP32 activation 版本能正确生成。Apple M4 Max 上 GPU 则明显占优：prefill 409 tok/s、decode 39.7 tok/s，对比 CPU 56 / 12.5 tok/s。

**判断：** 这条的价值不在“3B 模型已经适合手机”，而在于 looped-transformer 的 LiteRT-LM 导出和 SM8850 GPU 全图执行已经跑通。当前 2.4 GB 文件、约 8B 级的每 token 计算量、手机上 GPU/CPU decode 基本打平，决定它暂时不适合作为实际移动端替换模型；但它是很好的 LiteRT-LM 非标准 Transformer 架构兼容性案例。目前也没有 QNN/HTP NPU 路径。

**来源：** [LiteRT Community：Nanbeige4.2-3B](https://huggingface.co/litert-community/Nanbeige4.2-3B)

## AI 评测与研究

### Anthropic 发布 TASTE：测试模型能否判断 AI Safety 研究方案质量
`#Benchmark` `#AI-Safety`

**更新：** Anthropic 于 8 月 28 日发布 TASTE（The AI Safety Taste Evaluation），用于衡量模型在成对 AI safety 研究方案中做出研究质量判断的能力。最终 benchmark 包含 92 对方案，估算的人类研究者一致率为 77%；当前最佳模型 Fable 5 在标准设置下只有 60%，仍明显低于人类研究者。

**判断：** 这不是端侧业务候选，但属于值得保留的“新 benchmark”信号：前沿模型在 coding、agent 等可验证任务上的提升，并不等价于具备可靠的研究判断力。对未来自动化科研/自动数据筛选系统，judge model 的能力仍可能成为瓶颈。

## AI点评

- **今天端侧最值得看的其实是 Nanbeige4.2-3B，而不是它的绝对速度。** LiteRT-LM 已经能处理“22 层权重复用、执行两轮”的 looped-transformer，并在 SM8850 上做到 GPU 全图 delegation，说明转换链对非标准 Transformer 的覆盖正在扩展。
- **但 full delegation 仍然不能当性能结论。** Nanbeige 在 SM8850 上 GPU decode 和 CPU 基本打平，Granite 350M 昨天甚至出现 GPU decode 慢于 CPU；手机端评估仍必须拆开看 prefill、decode、峰值内存、功耗和正确性。
- **Hy4 preview 更值得作为架构雷达，而不是部署候选。** Gated DSA + IndexCache + MTP 体现的是服务器推理效率方向；真正与移动端相关的信号，要等这些设计是否被下放到 0.5B–4B 尺寸。
- **EmbeddingGemma/SM8850 继续高优先级跟踪。** 300M embedding 模型 + Qualcomm NPU 才是与本地语义搜索/相册检索真正匹配的组合；等 S26/SM8850 benchmark 正式进入模型卡后，再判断相对 S25 Ultra 的代际收益。
