## 模型与多模态

### NVIDIA Nemotron 3.5 Bolt E4B 新增 LiteRT-LM 手机 NPU 包与真机对照

**标签：** LiteRT-LM；Qualcomm NPU

**更新：** LiteRT Community 公布 NVIDIA Nemotron 3.5 Bolt E4B（基于 Gemma 4 E4B 后训练）的 LiteRT-LM 转换与 **10月26日 Galaxy S26（SM8850）实测**：CPU/GPU INT4 包 **4.40GB**，SM8850 专用 AOT NPU 包 **5.04GB**，许可 OpenMDW-1.1，转换包仅包含文本部分。以 1024-token prefill、256-token decode 测试，GPU 为 **868 / 15.2 tok/s**，NPU 为 **742 / 12.2 tok/s**（prefill / decode），NPU TTFT **1.47秒**、进程峰值内存 **3.88GB**；GSM8K NPU 99题中答对92题，与该子集 BF16 参考一致。数字来自转换者的设备测试，并非 NVIDIA 官方独立 benchmark。

**判断：** 这比“可以编译”更进一步，已证明特定 SM8850 + QAIRT 2.47.0 + LiteRT-LM main 构建可实际在 NPU 执行，但没有完整 graph partition/fallback 证据，不宜断言 **full delegation**；同条件下 NPU 的 prefill、decode 均慢于 GPU，也不能称为已加速。SM8750/SM8845、正式版 LiteRT-LM、中文 tool calling、功耗和多轮会话仍需单独验证。混合 INT8/INT4 权重、INT16 激活及 3.5GiB 单图限制值得参考。

**来源：** https://huggingface.co/litert-community/NVIDIA-Nemotron-3.5-Bolt-E4B

## 音频、翻译与检索

### 腾讯 Hy-SimulMT 正式开源：中英双向实时同传，提供 FP8 / GGUF

**标签：** Simultaneous MT；Speech Translation

**更新：** 腾讯混元 **10月26日**发布 **Hy-SimulMT-30B-A3B** 系列（30B 总参数、约3B 激活），提供仅译文和原文/译文交错输出两种模式，均有原始、FP8、GGUF 包，Apache-2.0。项目公开 SimulInfer 流式服务与 SimulTrain 训练工具，支持中英双向实时同传；官方 RealSI 长音频自测 **StreamLAAL 约3秒**，并提供 Hy Translate Android/iOS 应用。语音合成和声音克隆需要**额外配置 TTS 服务**，不能将其视为单模型原生完成全部 ASR→MT→TTS。

**判断：** 对端侧 Live Translation 最值得研究的是增量翻译策略、StreamLAAL 与翻译质量的权衡，以及 FLEURS/CoVoST2/RealSI 对照；**StreamLAAL 不等于首个语音包延迟**。30B 总权重即使只激活3B也不等于手机3B模型；官方部署主要依赖 NVIDIA GPU/vLLM，GGUF 包也尚不能证明 Android/QNN/HTP 可运行，官方说明对应 llama.cpp 音频支持仍待合并。

**来源：** https://huggingface.co/tencent/Hy-SimulMT-30B-A3B-Interleave · https://github.com/Tencent-Hunyuan/Hy-SimulMT

### sherpa-onnx v2.0.1：集成 VoxLock 目标说话人隔离与 Android API

**标签：** ASR Front-end；Android / Kotlin

**更新：** sherpa-onnx 于 **10月26日 23:24（北京时间）**发布 **v2.0.1**，正式集成 VoxLock 目标说话人隔离，新增模型/测试数据及 C/C++、Java/Kotlin、Swift、Dart、WebAssembly 等 API；同时修复 Canary greedy search token 位置、NeMo 流式 CTC fbank 与 Kokoro INT8 STFT 精度问题。VoxLock 原项目早于本日发布，是此次 **runtime 集成**的新进展：约 **27M** 参数、Apache-2.0，INT8 ONNX 约 **75MB**；作者在 Apple M2 Pro 40ms 分块、4线程测得 **RTF 0.69**，并报告约24ms算法延迟（不含自动获取约3秒说话人样本的等待）。

**判断：** 对多人对话/背景人声干扰下的端侧 ASR 很有实验价值，可在现有英文热词测试集前增加“目标说话人隔离→ASR”，同时评估 WER、背景词泄漏、FTL、额外 RAM 与功耗。Java/Kotlin API 可用不等于 Android 手机实时性能已验证，更不等于 SM8750/SM8845 NPU 委托。

**来源：** https://github.com/k2-fsa/sherpa-onnx/releases/tag/v2.0.1 · https://github.com/arbazsiddiqui/voxlock

## AI点评

1. **最值得立即关注的是 SM8850 上 LiteRT-LM 的真实 NPU 数据。** Bolt E4B 的 NPU 确实运行，但在所报条件下慢于 GPU；下一步应优先获取 graph partition、HTP 负载、功耗与 SM8750/SM8845 兼容性，而不是只看 NPU 标签。
2. **同传评估应把质量、滞后和语音首包拆开。** Hy-SimulMT 的 StreamLAAL、现有 OPUS-MT/LLM 翻译的 AL/FTL/E2E latency 应统一口径后再比较。
3. **ASR 前处理出现可复用的新组件。** VoxLock 适合测试“背景人声导致的误识别”，但要把说话人 enrollment、实时处理成本和普通安静场景退化一并测量。
4. **端云 Agent 的竞争重点从单次模型分数转向任务成本与执行边界。** Terra 的 Computer Use 进展和 Anthropic 的风险披露说明成功率、权限隔离、可审计性需要共同评估。
