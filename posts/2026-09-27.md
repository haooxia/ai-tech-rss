## AI 行业热点

### 跟进｜非当日发布・社区热度上升：Ollaya 把 Jev-style 决策模型做成“本地 Ollama”
`Decision Model` `Local Agent`

**更新：** Ollaya 是 9 月 23 日公开的 Apache-2.0 本地 decision-model runtime，本身不是今天首发；但过去 24 小时明显进入社区扩散期，Hacker News 讨论升温，GitHub 项目也快速增长。它把 Laya、Decider、Kev、NLI、GLiClass、Qwen3Guard 等开放模型统一到一个类似 Ollama 的本地 CLI/daemon 中，并直接兼容 TypeSafe 的 `/v1/systemone` API：现有 Jev 客户端只需改 base URL 即可切到本地模型。运行层目前以 ONNX Runtime CPU/CUDA 为主，GGUF 模型走 llama.cpp；其中 Laya multilingual 为 322M、Laya English 为 421M，Decider 有约 0.8B/2B，Kev 默认约 0.8B，并提供 MCP server 与 Agent skill。

**判断：** 这比单个“Jev 替代模型”更值得关注，因为 System One / decision model 开始形成真正的本地运行时生态：同一 API 可以替换多个 0.3B–2B classifier/router，而不必把所有决策交给生成式 LLM。对手机端尤其值得继续追，但当前官方发行目标仍是 Linux/macOS/Windows/Docker，没有 Android AAR、LiteRT/MNN/QNN 路径，也没有手机 RAM/latency/NPU 数据；因此目前只能算“架构候选”，不能算 Android 可部署方案。官方 RTX 4090 的 8–10 ms 与 Jev 云 API 236–276 ms 也不是同条件比较，不能直接当性能结论。

## AI点评

1. **Ollaya 是今天最值得继续追的项目。** 前几天 Jev、CLM、Needle 3 还是“几种模型路线”的竞争，现在已经开始出现类似 Ollama 的统一 decision-model runtime；这意味着 specialized decision model 可能正在从单点模型变成 Agent 基础设施层。
2. **对手机端，最值得试的不是 8B CLM，而是 Ollaya 里 322M–800M 这一档。** Laya multilingual、Decider 0.8B、Kev 0.8B 的尺寸已经进入移动端可研究区间；下一步关键是能否转 LiteRT/MNN/ONNX Runtime Mobile，以及中文 tool-routing / intent / score 的实际质量。
3. **这条路线和 Needle 3 很适合做正面对照。** Needle 3 是几十 MB 的专用 tool-calling 模型；Ollaya/Laya/Decider 是“state + typed questions → calibrated probabilities”的 decision layer。前者适合直接输出 tool/args，后者更适合 router、guard、置信度判断和多候选选择。
4. **端侧 NPU 今天仍没有新证据。** 继续坚持“可编译 → 可运行 → full delegation → 实际更快”；尤其不要因为一个 0.3B–0.8B 模型能在桌面 CPU/GPU 跑得快，就推断它在 Snapdragon HTP 上也会快。
